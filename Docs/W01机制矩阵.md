# W01 第一章机制矩阵

> 文档性质：M1 数据契约；为 M2 六个敌人原型规定可执行规则，不代表这些敌人已经制作完成。
> 版本：2026-08-21 / `W01-M1-v3`

## 一、共同约束

- 下表中的数值均为 `project-tuned` 初始值，不宣称来自《月圆之夜》当前版本；进入 M2 后只能根据固定 Seed 模拟和人工试玩调整。
- 同一机制必须由稳定 `MechanicId` 标识。运行时不得以敌人显示名、中文文本或模型判断规则，也不得根据职业、手牌或历史胜率暗改数值。
- 现有 `Damage / Block / Heal / Draw / ApplyStatus / RemoveStatus / GainAction / GainMana / DiscardRandom` 优先由卡牌效果数组表达。只有跨卡牌时机、条件判断或临时牌注入才进入通用机制执行器。
- 新通用规则必须使用与战斗牌组相同的确定性随机流，且不额外消费路线或奖励随机流。若规则不需要随机，禁止为了表现调用随机数。
- 每次条件规则触发都输出 schema v2 等价结构化事件 `MechanicTriggered`，至少记录 `mechanicId`、触发时机、回合、目标、数值、触发前后状态和自动/人工来源。未触发不逐帧刷日志。
- 路线石台显示敌人名称、层级、危险度和一行被动摘要；战斗 HUD 显示完整被动、公开下一张牌、状态层数及有期限机制的剩余回合。规则结果先结算，再刷新 UI 和播放表现。
- M2 不为六名敌人编写 `if (EnemyId == ...)` 专属分支。确需 C++ 的部分只实现可复用的触发、条件和效果原语，并由敌人资产引用。

## 二、通用机制数据边界

建议在 M2 增加数据结构 `FFantasyCombatMechanicRule`，由敌人定义保存规则数组。首轮只开放下列有限语法，避免制作通用脚本语言：

| 维度 | 首轮允许值 | 运行契约 |
|---|---|---|
| 触发 | `BattleStarted`、`EnemyTurnStarted`、`EnemyAttackResolved`、`PlayerCardResolved`、`DamageResolved` | 每个权威结算点只派发一次；表现回调不得派发 |
| 条件 | 来源/目标、卡牌标签、实际生命伤害、当前格挡、每回合/每战次数、机制抑制回合 | 所有条件同时满足才触发，阈值在资产中显式保存 |
| 效果 | 现有组合效果、`AddTemporaryCard`、`LoseMana`、`SuppressMechanic` | 按数组顺序结算；临时牌只存在于本场战斗 |
| 次数 | 不限、每回合一次、每战一次 | 次数由 `(MechanicId, Scope)` 计数，开始新回合/战斗时清理 |
| 时限 | 立即、若干完整回合、本场战斗 | 剩余回合在对应阵营回合开始时递减，不依赖帧时间 |

首轮不支持任意表达式、脚本字符串、反射函数名或蓝图事件名。若一个机制无法用上述有限语法诚实表达，先扩展通用原语和测试，再制作资产。

## 三、六个原型的权威矩阵

| 敌人 / `MechanicId` | 触发时机 | 条件 | 目标与效果 | 持续、叠加与清除 | UI / 日志 | 实现选择 |
|---|---|---|---|---|---|---|
| 森林狼 / `ForestWolf.Pursuit` | 每张敌方攻击牌完成伤害结算后 | 本次对玩家造成实际生命伤害；命中前玩家格挡不高于 2；本敌方回合尚未触发 | 对玩家立即造成 3 点不穿刺、不接受力量加成的追击伤害 | 每个敌方回合最多一次；立即结算；战斗结束清零 | 被动摘要显示“低格挡受伤会被追击 3”；触发时战斗消息和 `MechanicTriggered` 显示命中前格挡、首次伤害和追击伤害 | 新增通用 `EnemyAttackResolved + PlayerBlockAtMost + OncePerTurn` 规则；追击使用现有效果数组，不写狼专属 C++ |
| 毒蜘蛛 / `PoisonSpider.VenomDeck` | 毒牙/喷毒牌被打出时；玩家回合结束时由现有中毒结算 | 牌可支付并正常结算；中毒层数大于 0 才跳伤害 | 卡牌为玩家叠加 1–2 层中毒；玩家回合结束受到当前层数伤害，然后层数减 1 | 多张牌加法叠加；`RemoveStatus(Poison)` 按数值净化；战斗结束清零 | HUD 始终显示中毒层数和回合结束伤害；公开牌写明将叠加层数；沿用 `W01_POISON_TICK` 并补标准状态变化事件 | 完全复用现有卡牌效果和中毒状态；M2 同批至少提供一个可获得的净化入口，否则文案不得承诺“净化”反制 |
| 树妖 / `Treant.Growth` | 每个敌方回合开始；玩家卡牌造成伤害后检查火焰标签 | 生长未被抑制时；火焰抑制要求来源卡含 `Archetype.Fire` 且实际造成大于 0 的生命或格挡伤害 | 正常回合获得 5 格挡；被火焰命中后跳过下一次生长 | 生长格挡按既有格挡规则保留到下次敌方回合开始时清空；火焰抑制固定 1 次敌方回合，多次命中只刷新为 1，不叠加 | 被动区显示“生长可用/被火焰抑制 1 回合”；火焰命中和跳过生长分别记录 `MechanicTriggered` | 新增通用 `EnemyTurnStarted`、来源卡标签条件和 `SuppressMechanic`；格挡仍用现有效果数组，不写树妖专属 C++ |
| 酒馆醉鬼 / `TavernDrunk.UnsteadyDeck` | 敌方按公开手牌正常出牌 | 由确定性洗牌决定抽到低伤或高伤牌；撒酒牌须可支付 | 低伤牌 3 点、高伤牌 9 点；撒酒按顺序随机弃掉敌方手牌 1 张、玩家手牌 1 张 | 伤害与弃牌立即结算，不跨回合叠加；无牌可弃时安全得到 0 | 下一张牌继续公开，不能把 3/9 隐藏成一次即时随机；弃牌消息列出双方实际弃牌数 | 完全复用现有敌方牌组、确定性洗牌和两个 `DiscardRandom` 效果；禁止额外 `RandRange` 决定伤害 |
| 巡林猎人 / `RangerHunter.Longbow` | 长弓装备牌结算后；后续攻击伤害计算时 | 长弓已在敌方装备区；攻击牌正常结算 | 长弓提供 `EquipmentAttackBonus=2`，后续每张攻击牌获得 +2；首轮牌组只放 1 张长弓 | 装备在本场战斗持续，不可重复叠加；战斗结束清除。若未来允许摧毁装备，移出装备区即失效 | HUD 装备区显示“长弓 +2 攻击”，公开攻击预览包含最终伤害；装备与攻击事件保留 CardId | 完全复用现有 Equipment 区和攻击加成；不需要被动分支，`PassiveId` 只用于说明文本 |
| 女巫侍徒 / `WitchAcolyte.HexMana` | 诅咒牌或汲取法力牌结算时 | 玩家牌组运行时有效；临时诅咒资产通过静态校验；扣法力时最低到 0 | 诅咒牌向玩家弃牌堆加入 1 张本战临时【枯竭咒】；该牌 0 费、打出后失去 1 法力并消耗。汲取法力直接令玩家失去 2 法力 | 临时牌可多张叠加但总数上限 3；超限时不再加入并记录 `capped=true`；只存在本战，扣法力不产生负值 | HUD 牌区数量立刻变化；诅咒规则写明 0 费/失去法力/消耗；日志记录注入、上限、实际扣除量 | 新增通用 `AddTemporaryCard`、`LoseMana` 以及临时牌清理；两者可供后续 Boss/事件复用，不写女巫专属 C++ |

## 四、反制与可读性底线

| 原型 | 玩家必须能观察到 | 至少一种首轮反制 |
|---|---|---|
| 森林狼 | 追击阈值、每回合是否已触发 | 在攻击前保留 3 点以上格挡，或阻止首次生命伤害 |
| 毒蜘蛛 | 当前层数、回合结束预计伤害 | 速杀；或用明确的 `RemoveStatus(Poison)` 牌净化 |
| 树妖 | 下一次是否生长、火焰抑制剩余次数 | 用 `Archetype.Fire` 伤害跳过下一次 5 格挡，或用高爆发越过成长 |
| 酒馆醉鬼 | 下一张是 3 还是 9 点、双方弃牌结果 | 根据公开高伤牌提前防御；关键牌可提前打出或保留机制保护 |
| 巡林猎人 | 长弓是否装备、所有攻击的最终预览 | 在装备前压制，或围绕已公开的固定 +2 提前计算格挡 |
| 女巫侍徒 | 临时诅咒数量、打出代价、当前法力 | 尽早零费消耗诅咒，控制法力储备，避免关键咒术回合被汲取 |

如果 UI 无法展示上述信息，该机制不能进入人工试玩。模型、动画、颜色和音效只增强反馈，不能成为唯一规则提示。

## 五、M2 实现与门禁顺序

1. 先为通用机制规则、临时牌注入和失去法力建立纯规则测试；固定 Seed 下重复运行必须得到相同触发序列。
2. 为 `MechanicId`、触发类型、次数范围、卡牌标签、临时牌引用及数值范围增加静态校验；非法规则不进入战斗，输出明确错误并采用无被动安全回退。
3. 先制作毒蜘蛛、酒馆醉鬼和巡林猎人三个纯数据原型，验证现有组合效果足够；再实现森林狼、树妖和女巫侍徒需要的通用原语。
4. 每个敌人至少增加一项自动规则测试和一场固定 Seed 模拟战斗，确认触发次数、牌区、资源、状态与终局可结算。
5. 六个原型全部通过静态校验和模拟后，才加入第一章章节遭遇池并进行人工试玩；不得只因资产已生成就标记为可玩完成。

M1 到此只冻结机制语义和实现边界。敌人资产、卡牌、通用执行器、UI 变化与数值调优属于 M2。
