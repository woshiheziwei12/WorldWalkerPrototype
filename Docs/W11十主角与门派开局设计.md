# W11《太虚问道》十主角与门派开局设计

版本：W11-M1-v2  
日期：2026-08-29  
状态：已进入项目实现与自动化验证

> 目标玩法以 `Docs/W11核心体验冻结表.md` 为准。通用闪避使用 `Space`，技能化普通攻击使用 `F`，四主动技能槽当前使用 `Q/W/E/R`；发布默认值、手柄和重绑定布局仍待验收。

## 1. 目标与边界

“独自启程”不再直接开战，而是完成一次可回退、可确认的角色创建：

`入口主页 → 选择化身 → 选择门派 → 服务端校验 → 写入本局状态 → 第 1 重试炼`

- 化身决定两项先天属性，只作用于当前一局。
- 门派与化身完全独立，10 名主角均可加入 6 个门派，共 60 种开局组合。
- 门派决定一个可立即使用的初始术法，并把它加入玩家的 `Active1`；当前原型按 `Q` 施展，其他主动技能可放入 `W/E/R` 对应槽。
- 普通攻击由独立 `BasicAttackAbility` 决定；闪避是所有角色共有且不占技能槽的基础能力。
- 十名角色共用同一套普通攻击、主动技能定义、规则效果和技能表现。角色不会产生技能专属变体。
- 玩家确认前仍处于 `Lobby`，不会生成敌人，也不会提前结算随机内容。
- 角色、门派、术法都使用 Primary Data Asset；UI 只读取数据，不持有权威规则。

## 4. 入口交互

### 4.1 选择化身页

- 页面改为左右分栏：左侧两列五行显示 10 张独立圆形头像，右侧只展示当前角色的一张大型透明全身立绘。
- 当前头像以青白灵光和轻微放大强调；悬停态使用较弱的青玉亮度，不再使用姓名按钮代替头像。
- 右侧以月轮、玉台和云雾构成空角色舞台；姓名、称号、两项先天禀赋与人物简介位于独立说明区，人物从头到脚保持可见。
- 当前立绘使用 526.67×790 的固定 2:3 显示矩形，布局相对初版向右固定偏移 68 Slate 单位；运行时仍保持 `Scale=1 / Translation=0 / Rotation=0 / Opacity=1`，切换角色也不播放缩放、位移或淡入。立绘后方两层通用青玉仙气与人物同心，位置、缩放和旋转均固定，仅以不同周期在接近消失与高亮之间改变透明度，永不修改人物本体。
- “返回主界”回到入口主页；“选定此身”进入门派页。

### 4.2 选择门派页

- 页面不显示六门派卡片、标题、说明、术法名或数值；当前门派的 16:9 `SelectionArtwork` 直接替换根 `BackgroundImage` 并铺满视口，画面本身承担门派气象展示。
- 页面底部中央只保留小型“左箭头／门派名／右箭头”轮播器，点击箭头循环切换六个门派并同步替换全屏背景；键盘左右方向键提供相同操作。
- “返回择人”缩至左下角，“确认门派”位于右下角；Enter 可直接确认当前门派。三处控件之外不再用面板、缩略图或文字遮挡背景。
- 门派页与人物页属于同一角色创建阶段：二者均隐藏标题页流雾与灵尘，并连续播放人物选择音乐；切页不会重启或交叉淡化同一首曲目。
- “返回择人”保留当前门派并回到角色页；“确认道途·独自启程”提交两项 ID。
- `Esc` 在门派页返回角色页，在角色页及其他子页返回主页。

### 4.3 服务端契约

客户端只提交 `HeroId + SectId`。`AW11GameMode::StartSoloRun` 必须在当前 `DA_W11_RunRules` 的白名单中重新查找角色和门派，再由门派解析初始术法。校验通过后把 `SelectedHeroId`、`SelectedSectId`、`InitialAbilityId` 写入 `AW11PlayerState` 并复制；非法 ID 不开局。

无界面测试可使用：

```text
-W11AutoStart -W11Hero=Jia -W11Sect=ThunderManor -W11RunSeed=424242
```

自动开局若未指定 ID，使用规则集中的第一名角色和第一个门派，保证冒烟测试与联机旧入口不被 Lobby 卡住。

## 5.1 角色选择头像

每名主角另有一张 1254×1254 的头肩头像，不用缩放全身立绘冒充头像。头像以原全身立绘作为身份参考，保留脸型、发式、性别、年龄感和服装主色，统一使用墨玉圆章、青玉与旧金细边；圆章外已处理为真实 Alpha。源文件位于 `SourceArt/W11/Heroes/Avatars/W11_Hero_<Key>_Avatar_v1.png`，Unreal 资产位于 `Art/Heroes/Avatars/T_W11_Hero_<Key>_Avatar`。`UW11HeroDefinition::Avatar` 单独保存选择头像，`Portrait` 继续只负责右侧全身立绘，避免两类 UI 资源互相替代。

## 6. 当前验证标准

1. Editor 与 Game 目标均可完整编译。
2. 规则资产恰好包含 10 名主角与 6 个门派；5 男 5 女；ID 唯一。
3. 每名主角至少两个先天 Modifier，头像与全身立绘均可加载。
4. 每个门派都有不同的初始术法。
5. 选择页在 1280×720 下显示 2×5 十头像、右侧全身像和详情，人物头脚不得裁切，根背景必须被专属场景完整替换且不能露出标题页旧背景；门派页不得出现六门派卡片，只显示全屏门派画卷、底部小型箭头/门派名轮播器与右下角确认入口，切换时背景立即更新且人物选择音乐保持连续播放。
6. 指定 `Hero.Jia + Sect.ThunderManor` 开局时，日志必须显示会心已加成并绑定 `Ability.FiveThunder`。
7. 当前原型的 `Space` 施法由服务器扣除真元、校验调息并产生 `W11_INITIAL_ABILITY_CAST`；迁移到四个主动技能槽后，同一校验适用于任意槽位。
8. 任意两名角色装备同一普通攻击或主动技能时，必须解析到相同的能力定义和技能表现资产，不存在角色专属效果副本。
9. 所有角色都能请求独立基础闪避，闪避不占普通攻击或四个主动技能槽。
