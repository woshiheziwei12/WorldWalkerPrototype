## 1. 证据判定规则

- **已证明**：当前工作树中存在直接实现和与要求同范围的通过证据。
- **工具就绪，待真人**：采集、拒绝伪证和汇总工具已完成，但不存在真人完成的正式证据包。
- **待外部环境**：工程边界存在，但当前机器、账号或 App ID 不能证明发布环境行为。
- **待内容冻结**：继续实现会替产品决定仍明确标注为待确认的玩法内容。

自动化、脚本日志和截图只证明各自覆盖的事实，不用于替代真人手感、耳机混音、好玩程度或真实 Steam 网络结论。

### 4.2 真实 Steam 双机发布门禁

当前配置使用 Null 作为默认平台服务，Steam 开发 ID 是公共测试 ID `480`。正式 runner 与 schema 2/5 收据链继续验证 Scenario、项目 App ID、Cooked 运行时、Token、PackageHash、SessionId、人数、Steam64、包/套件身份及双时点完整性。Final43 v8 的只读环境预检先解析当前活动网络 Profile，再检查 ActiveStore 中适用于这些 Profile 的启用入站 Allow 规则；本机实测 Python 3 与包/套件身份通过，但 `SteamClient=NOT_RUNNING`，网络/防火墙 ActiveStore 查询为 `ACCESS_DENIED`，输出保持 `FormalSteamGate=PENDING`。该结果与用户截图中“此设置由你的组织进行管理、允许按钮禁用”一致，只能作为管理员处理依据，不能证明网络已放行。预检不会执行任何 `New/Set/Remove-NetFirewallRule` 或 `netsh advfirewall`；真实门禁仍需要项目 App ID、已登录且身份互异的授权账号、组织管理员放行，以及五场景跨机日志。NAT、重连和未冻结的房主恢复/迁移策略仍需独立证据。

五章候选路线已经在战斗前声明 transition ownership、消费 `FW11CombatNodeResult`，并把仙坊迁移为安全地图节点；五张独立地图资产、五名剧情小 Boss、顾长渊三阶段最终 Boss 和单活动局安全续玩均有直接实现及日志证据。当前剩余门槛不是继续补占位接口，而是由产品/测试人员确认每章普通战斗、事件、休整、仙坊和支路的具体数量，核对五张地图的实际视觉与路线体验，并在章节证据中写入 `contentFrozen=true` 与非空 `verifiedBy`。在此之前，候选证据必须保持未冻结状态。
