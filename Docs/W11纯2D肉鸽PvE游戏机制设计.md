## 1. 机制定位

W11 暂定为纯 2D 俯视角动作肉鸽 PvE：

- 单人可完整游玩；
- 保留 1～4 人 Steam 好友合作；
- 玩家在平面内上下左右移动并攻击怪物；
- 每局从基础能力开始，通过随机升级形成不同构筑；
- 正式目标是一局约 50 分钟的章节路线，同时保持 Seed 可复现和联机权威；
- 不设计 PvP、排位或玩家互相伤害。

采用“章节路线 + 战斗节点 + 安全升级节点”的结构。五章各自以一场小 Boss 战结束，之后进入最终 Boss；合作联机中的个人升级仍在安全节点处理，不在战斗中暂停世界。

## 2. 推荐的核心循环

```text
进入 W11
  ↓
选择角色/门派并配置起始普通攻击技能
  ↓
第一至第五章路线
  ├── 移动、攻击、释放耗蓝技能
  ├── 击败怪物获得团队经验
  ├── 拾取生命、法力和宝箱
  ├── 经过战斗、事件、休整或地图仙坊节点
  └── 击败本章小 Boss
  ↓
安全升级间隔
  ├── 每位玩家独立三选一
  ├── 可消耗重投/锁定/跳过
  └── 更新个人构筑
  ↓
下一章路线
  ↓
最终 Boss
  ↓
结局结算，或死亡后开始下一次轮回
```

单局目标中位数约 50 分钟，允许落在约 45～55 分钟。五章各约 7～8 分钟，最终 Boss 与结算约 8～10 分钟；时间、节点数和 Boss 预算仍必须数据化，以便试玩调整。

## 3. 操作建议

### 3.1 键鼠

- `WASD`：移动；
- 普通攻击：调用当前装备的 `BasicAttackAbility`，攻击方式由技能定义；最终使用方向键、鼠标瞄准还是可切换方案仍待试玩冻结；
- `Space`：所有角色共有的基础闪避键位，不占技能槽；当前原型已实现服务器校验的冷却、位移与短暂无敌；
- `F`：共享普通攻击；`Q / W / E / R`：四个主动技能逻辑槽。W11 当前使用方向键移动，因此该试玩布局无移动冲突；发布默认值仍应支持重绑定并单独设计手柄映射；
- `Tab`：查看属性和当前构筑；
- `Esc`：菜单。

### 3.2 手柄

- 左摇杆：移动；
- 右摇杆：瞄准，量化为四方向或八方向；
- 扳机/肩键：普通攻击和主动技能；
- 面键：闪避、交互和技能。

### 3.3 推荐攻击模式

目标模式是“技能定义普通攻击 + 四个主动技能槽 + 通用闪避”：

- 普通攻击不是角色硬编码动作，而是一个始终可用的 `BasicAttackAbility`；
- 技能定义其方向、索敌、投射物、近战范围、攻击间隔和资源规则；
- 所有角色共用同一套普通攻击和主动技能效果，角色只提供外观、通用动作和先天属性；
- 闪避独立于技能槽，保证任何构筑都有基础生存操作；
- 方向键、鼠标瞄准或自动索敌只属于输入/目标选择策略，不改变能力规则资产。

## 4. 属性体系总览

属性分为四层：

```text
生存属性
├── 最大生命、当前生命
├── 护甲、护盾、生命恢复
└── 移动速度、闪避无敌时间

资源属性
├── 最大法力、当前法力
├── 法力恢复
└── 技能消耗、资源获取效率

输出属性
├── 攻击力、攻击速度/技能急速
├── 暴击率、暴击伤害
├── 攻击距离、作用范围、持续时间
└── 投射物数量、投射物速度、穿透

成长与探索属性
├── 幸运
├── 拾取范围
├── 经验获取
└── 重投、锁定、跳过次数
```

玩家主界面不需要一次展示全部属性。HUD 只显示生命、法力和关键状态；完整属性放在 `Tab` 构筑页面。

## 5. 第一版必须存在的玩家属性

| 属性 | 内部建议名 | 作用 | 第一版建议 |
|---|---|---|---|
| 当前生命 | `Health` | 归零后倒地或死亡 | 必须 |
| 最大生命 | `MaxHealth` | 生命上限 | 必须 |
| 当前法力 | `Mana` | 释放主动技能 | 必须 |
| 最大法力 | `MaxMana` | 法力上限 | 必须 |
| 法力恢复 | `ManaRegenPerSecond` | 每秒自然恢复法力 | 必须 |
| 攻击力 | `Power` | 统一放大伤害和治疗基值 | 必须 |
| 移动速度 | `MoveSpeed` | 平面移动速度 | 必须 |
| 攻击速度 | `AttackSpeed` | 普通攻击频率 | 必须 |
| 技能急速 | `AbilityHaste` | 缩短主动技能冷却 | 建议 |
| 护甲 | `Armor` | 降低受到的直接伤害 | 必须 |
| 暴击率 | `CritChance` | 触发暴击的概率 | 建议 |
| 暴击伤害 | `CritMultiplier` | 暴击倍率 | 建议 |
| 幸运 | `Luck` | 影响稀有结果和掉落品质 | 必须 |
| 攻击距离 | `AttackRangeScale` | 攻击最远距离 | 必须 |
| 作用范围 | `AreaScale` | 爆炸、光环和碰撞体尺寸 | 必须 |
| 拾取范围 | `PickupRadius` | 自动吸取经验和掉落 | 建议 |

第一版先不要加入命中率、闪避率、元素精通、韧性、护甲穿透、多个独立抗性等复杂属性。它们会增加 UI 和平衡成本，但对最小玩法闭环帮助不大。

## 7. 幸运机制

### 7.1 幸运应该影响什么

推荐让幸运影响：

- 升级三选一出现较高稀有度的权重；
- 宝箱品质；
- 生命球、法力球或功能掉落的出现概率；
- 重投后避免重复低品质选项的概率；
- 少量特殊事件的正向结果。

幸运不直接影响：

- 普通攻击是否命中；
- 暴击率；
- 伤害随机浮动；
- Boss 是否掉落必需进度物品；
- 关卡能否通关。

暴击率已经是独立属性。如果幸运同时提高暴击，它会成为同时增强输出和资源的万能属性，容易压制其他选择。

### 7.2 幸运使用递减收益

建议内部使用有效幸运：

```text
EffectiveLuck = Luck / (Luck + 100)
```

示例：

| Luck | EffectiveLuck |
|---:|---:|
| 0 | 0% |
| 25 | 20% |
| 50 | 33.3% |
| 100 | 50% |
| 200 | 66.7% |

每个系统再根据 `EffectiveLuck` 设置独立最大收益。例如：

```text
稀有升级权重倍率 = 1 + EffectiveLuck × 0.75
普通功能掉落倍率 = 1 + EffectiveLuck × 0.50
宝箱高品质权重倍率 = 1 + EffectiveLuck × 1.00
```

这样幸运永远有用，但不会线性堆到破坏经济。

### 7.3 合作模式的幸运

推荐规则：

- 个人升级候选使用个人幸运；
- 个人宝箱使用个人幸运；
- 全队共享掉落使用存活玩家的平均幸运；
- Boss 固定奖励不受幸运影响；
- 不使用全队最高幸运，避免所有人都被迫让一名玩家堆“工具人幸运”。

所有幸运随机结果由服务器生成，客户端只接收候选和结果。

## 8. 范围机制

“范围”必须拆成至少三个属性，否则玩家和程序都会混淆。

### 8.1 攻击距离 `AttackRangeScale`

影响攻击能到多远：

- 子弹最大飞行距离；
- 近战挥砍前伸距离；
- 自动索敌最大距离；
- 锁链、激光或冲击波长度。

```text
FinalAttackRange = BaseAttackRange × AttackRangeScale
```

它不应该同时把爆炸半径变大。

### 8.2 作用范围 `AreaScale`

影响攻击有多宽、多大：

- 爆炸半径；
- 近战弧宽；
- 光环半径；
- 地面持续区域；
- 穿行路径宽度。

如果使用半径直接线性放大，实际面积会按平方增长。建议视觉和碰撞半径采用较温和公式：

```text
FinalRadius = BaseRadius × sqrt(AreaScale)
```

当 `AreaScale=2.0` 时，实际面积约翻倍，而不是半径翻倍导致面积变成四倍。

### 8.3 拾取范围 `PickupRadius`

只影响经验、金币、生命球、法力球和宝箱吸取，不影响攻击。

拾取范围是体验属性，可以让后期战斗更流畅，但不应无限扩张。建议设置地图尺寸相关上限。

### 8.4 持续时间 `DurationScale`

虽然不叫范围，但与范围构筑经常联动：

- 地面火焰持续时间；
- 光环或增益持续时间；
- 投射物存在时间；
- 控制效果持续时间。

建议把它独立出来，避免“范围”同时增加尺寸和持续时间。

## 9. 血量与生存机制

### 9.1 基础生命规则

- `Health` 范围为 `0..MaxHealth`；
- 增加最大生命时，推荐同时按增加量补充当前生命；
- 降低最大生命时，当前生命被截断但至少保留 1，除非该效果明确允许致死；
- 普通治疗不能超过最大生命；
- 直接伤害、持续伤害和环境伤害使用统一伤害入口。

### 9.2 护甲公式

推荐使用递减收益：

```text
DamageReduction = Armor / (Armor + 100)
FinalDamage = RawDamage × (1 - DamageReduction)
```

建议常规减伤上限为 75%。特殊无敌或机制免伤使用独立状态，不通过堆到无限护甲实现。

### 9.3 护盾

护盾建议作为临时生命池，而不是第二种永久血条：

- 伤害先扣护盾，再扣生命；
- 护盾通常有持续时间或触发条件；
- 多个护盾采用明确的覆盖、叠加或刷新规则；
- HUD 必须区分生命和护盾。

第一版可以只实现一个统一 `Barrier` 数值，不急于增加物理盾、魔法盾等分类。

### 9.4 生命恢复

恢复来源建议分为：

- 生命球或补给；
- 波次结束后的少量恢复；
- 被动生命恢复；
- 技能治疗；
- 击杀恢复或吸血。

第一版不建议同时开放强吸血和高被动回血，否则大量小怪会变成无限血包。优先使用有限掉落和波次恢复，更容易平衡。

### 9.5 单人死亡

已确认规则：

- 气血归零立即结束当前局内构筑并开始下一次轮回；
- 不在原地复活，也不从当前章节继续；
- 死亡清空技能配置、修为、秘籍、宝物、灵石、路线和活动局快照；
- 已提交的史料、众生证词、人物关系阶段、结局、图鉴和横向内容解锁进入“界痕”档案；
- 不保留永久气血、攻伐、护体、灵石或其他跨局数值优势；
- 主动退出或程序中断不视为死亡。约 50 分钟单局允许从最近已完成的地图安全节点继续。

### 9.6 合作倒地与救援

推荐合作模式不是立即死亡，而是：

```text
Health = 0
  ↓
Downed 倒地状态
  ├── 不能攻击
  ├── 可以缓慢爬行
  ├── 倒地计时持续衰减
  └── 队友持续交互救援
        ↓
      恢复部分生命 + 短暂无敌
```

规则建议：

- 全队同时倒地才失败；
- 每次倒地使本局后续倒地计时变短；
- 救援进度由服务器权威计算；
- 受到伤害是否打断救援需要后续试玩；
- 不允许倒地玩家无限拖延 Boss。

## 10. 蓝量与技能循环

### 10.1 法力定位

推荐法力只服务主动技能：

- 普通攻击不消耗法力；
- 主动技能同时受到法力消耗和冷却限制；
- 法力自然恢复，避免玩家完全失去技能；
- 少量攻击、拾取或被动可以额外恢复法力。

普通攻击如果也耗蓝，会出现蓝量耗尽后只能逃跑的负反馈，不适合作为第一版基础循环。

### 10.2 法力规则

```text
Mana = Clamp(Mana, 0, MaxMana)
CanCast = Mana >= ManaCost && CooldownReady && StateAllowsCast
```

法力恢复建议：

- 默认持续恢复；
- 释放技能后的短暂恢复延迟可以作为特定角色机制，而不是全局强制；
- 法力球立即恢复固定值或最大法力百分比；
- 法力恢复在倒地和死亡状态暂停。

### 10.3 冷却与技能急速

```text
FinalCooldown = BaseCooldown / (1 + AbilityHaste)
```

其中 `AbilityHaste=0.25` 表示 25% 急速，实际冷却约为原来的 80%。建议设置最短冷却下限，避免高急速使技能在网络中每帧触发。

### 10.4 合作模式中的法力掉落

建议：

- 法力球按玩家实例化，避免队友争抢；
- 或者拾取后为范围内所有队友恢复较小数值；
- 第一版不要使用“第一个碰到的人独占全部法力”的规则；
- 服务端决定归属和恢复，客户端只播放吸取表现。

## 11. 输出属性

### 11.1 攻击力

建议所有技能定义保存基础系数：

```text
RawDamage = AbilityBaseDamage × Power × AbilityCoefficient
```

如果以后需要加法增伤和乘法增伤，应明确计算层级：

```text
RawDamage
= 基础技能伤害
× Power
× (1 + 同类加法增伤总和)
× 独立乘法效果
```

### 11.2 攻击速度

攻击速度主要作用于普通攻击：

```text
FinalAttackInterval = BaseAttackInterval / AttackSpeed
```

建议为动画和网络请求设置最短间隔。攻击速度不能通过客户端播放更快动画来直接增加伤害。

### 11.3 暴击

```text
IsCritical = ServerRandom < CritChance
CriticalDamage = NormalDamage × CritMultiplier
```

建议：

- 初始暴击率 5%；
- 初始暴击伤害 150%；
- 暴击率常规上限 100%；
- 持续伤害是否暴击由能力定义声明；
- 治疗是否暴击第一版关闭；
- 幸运不直接提高暴击率。

### 11.4 投射物属性

后续可加入：

- `ProjectileCount`：一次发射数量；
- `ProjectileSpeed`：飞行速度；
- `PierceCount`：穿透目标数量；
- `BounceCount`：弹射次数；
- `Knockback`：击退强度。

这些应作为武器/能力相关属性，不一定全部显示在通用角色面板。

## 12. 状态效果

第一版推荐控制在少量、可读的状态：

### 玩家正面状态

- `Haste`：移动或攻击加速；
- `Barrier`：临时护盾；
- `Empowered`：下一次攻击强化；
- `ManaSurge`：短时法力恢复提高；
- `Regeneration`：持续恢复生命。

### 玩家和怪物负面状态

- `Burn`：持续伤害；
- `Slow`：移动减速；
- `Weaken`：输出降低；
- `Vulnerable`：受到伤害提高；
- `Stun`：短暂不能行动，Boss 需要抗性或递减。

每个状态必须定义：

- 来源和目标；
- 持续时间；
- 最大层数；
- 重复施加是叠层、刷新还是覆盖；
- 是否可驱散；
- Boss/精英修正；
- UI 图标和网络复制字段。

不要为每个技能创建只有名字不同、规则相同的新状态。

## 13. 普通攻击技能、主动技能与被动

推荐把构筑内容分成三类：

### 13.1 普通攻击技能

- 不耗蓝；
- 由当前装备的 `BasicAttackAbility` 完整定义攻击行为，不按角色名字硬编码；
- 受攻击力、攻击速度、攻击距离、作用范围等属性影响；
- 每名角色至少有一个永不失效的基础攻击；
- 所有角色从同一普通攻击技能池中选择，同一技能在不同角色身上的规则和特效一致。

### 13.2 主动技能

- 消耗法力；
- 有冷却；
- 可以是爆发、控制、位移、护盾或治疗；
- 每名玩家拥有四个主动技能逻辑槽 `Q / W / E / R`；
- 所有角色共用同一主动技能池和效果定义，不制作角色专属效果副本。

### 13.3 被动升级

- 修改属性；
- 改变能力行为；
- 增加触发器；
- 不占用主动技能按键。

第一版建议使用：

```text
1 个普通攻击技能槽
4 个主动技能槽（Q / W / E / R）
1 个独立基础闪避
4 个被动槽
每项最多 3～5 级
```

以后再讨论武器进化、组合公式和传奇改造，不在首个切片中同时实现。

## 14. 升级三选一

### 14.1 候选生成

服务器根据以下信息生成每位玩家的候选：

- 当前角色和允许内容池；
- 已拥有武器、技能和被动；
- 当前等级和前置条件；
- 内容稀有度；
- 个人幸运；
- 本局已出现和已拒绝内容；
- 内容版本和权威随机流。

### 14.2 稀有度

第一版建议四档：

```text
Common
Rare
Epic
Legendary
```

传奇效果优先改变玩法方式，而不是单纯提供巨大数值。例如“投射物返回”“火球落地留下燃烧区”比“伤害 +200%”更有构筑意义。

### 14.3 辅助选择资源

- `Reroll`：重投全部候选；
- `Lock`：锁定一个选项到下一次升级；
- `Skip`：放弃本次升级并获得小额补偿；
- `Banish`：本局不再出现某个选项，后续再考虑。

第一版只实现重投即可，其余功能根据试玩增加。

### 14.4 合作升级节奏

推荐团队共享经验等级，但每人获得独立候选：

- 避免队友争抢经验；
- 所有人同时进入安全升级阶段；
- 每个人形成不同构筑；
- 所有人确认或倒计时结束后进入下一波；
- 超时玩家由服务器按预设规则自动选择或跳过。

## 15. 经验、掉落与宝箱

### 15.1 经验

推荐怪物掉落经验能量，任何玩家拾取后增加团队经验：

- 经验属于团队，不按最后一击归属；
- 经验阈值随团队等级上升；
- 玩家人数影响怪物强度，不降低单个玩家升级体验；
- 超出地图或长时间未拾取的经验可以合并，降低 Actor 数量。

### 15.2 基础掉落类型

- 经验能量；
- 生命球；
- 法力球；
- 宝箱；
- 临时增益；
- 局内货币（如果以后需要商店）。

第一版可以先没有金币和商店，避免同时建设两套升级经济。

### 15.3 宝箱

- 精英和 Boss 掉落宝箱；
- 普通怪物只以低概率掉落；
- 宝箱品质受幸运影响；
- 合作模式中优先个人实例宝箱，避免抢夺；
- Boss 必需奖励固定，不受幸运影响。

## 16. 怪物体系

第一版怪物角色建议覆盖不同压力，而不是只换生命和颜色：

| 原型 | 作用 |
|---|---|
| 追逐者 | 基础近战，形成数量压力 |
| 远程者 | 迫使玩家移动和改变站位 |
| 冲锋者 | 用明显预警制造闪避窗口 |
| 坦克 | 高生命、低速度，阻挡路线 |
| 支援者 | 给附近怪物加速、治疗或护盾 |
| 精英 | 组合普通机制并提供宝箱 |
| Boss | 多阶段、强预警、固定通关节点 |

所有攻击必须提供足够清晰的 2D 预警：颜色、地面形状、方向线、音效和施法前摇。纯 2D 画面中同时出现大量怪物时，可读性优先于华丽粒子。

## 17. 遭遇与难度缩放

### 17.1 遭遇阶段

建议数据化阶段类型：

- 生存：持续一定时间；
- 清剿：击败规定敌人；
- 精英：击败一个或多个精英；
- 防守：保护目标；
- Boss：完成本局最终战。

第一版只需生存、精英、Boss 三类。

### 17.2 合作人数缩放

不建议只把所有怪物生命乘以玩家人数。推荐混合缩放：

```text
怪物生命：温和增加
怪物数量：主要增加项
精英数量：按阶段增加
怪物伤害：轻微增加或不增加
掉落/经验：保持每位玩家成长节奏
```

原型公式可以从以下方向开始：

```text
EnemyHealthMultiplier = 1 + 0.45 × (PlayerCount - 1)
SpawnBudgetMultiplier = 1 + 0.70 × (PlayerCount - 1)
EnemyDamageMultiplier = 1 + 0.10 × (PlayerCount - 1)
```

这些数值必须通过试玩调整。合作模式的乐趣来自更多目标和配合，不应只是把怪物变成血厚的木桩。

## 18. 随机数与可复现性

服务器创建 `RunSeed`，并派生互不干扰的随机流：

```text
EncounterStream
EnemySpawnStream
UpgradeOfferStream_PlayerN
LootStream
ChestStream
CosmeticStream
```

要求：

- 某个玩家重投升级不能改变下一波怪物；
- 视觉随机不能改变掉落；
- 相同内容版本、Seed 和玩家决策可以复现关键事件；
- 运行日志记录 Seed、流消费序号和候选 ID；
- 客户端不生成权威掉落和升级结果。

## 19. 联机合作规则

第一版推荐：

- 关闭友军伤害；
- 团队共享经验等级；
- 玩家拥有个人构筑和个人幸运；
- 生命/法力掉落个人实例化或团队小范围共享；
- 宝箱个人实例化；
- 队友可以救援倒地玩家；
- 全队倒地才失败；
- 房主退出则本局结束；
- 普通客户端掉线不立即结束本局；
- 不实现物品交易和掉落争抢。

这些选择能优先减少合作中的负面竞争。

## 20. 属性修改的计算顺序

所有属性按统一层级计算，避免不同系统各自修改最终值：

```text
1. 角色基础值
2. 武器/技能基础修正
3. 本局永久升级的加法修正
4. 本局永久升级的乘法修正
5. 临时 Buff/Debuff
6. 难度和人数修正
7. 最小值/最大值限制
8. 得到最终运行时属性
```

建议使用统一 `FW11StatModifier`：

```text
StatId
Operation = Add | Multiply | Override
Magnitude
SourceId
Duration
StackPolicy
```

同一来源重复应用时必须知道是叠层、刷新持续时间还是替换较弱效果。

### 常驻 HUD

- 当前/最大生命；
- 当前/最大法力；
- 护盾；

## 23. 最小可玩版本内容范围

正式单局目标范围调整为：

- 章节路线地图；
- 现有十名角色共用一套普通攻击与主动技能池；
- 1 个普通攻击技能槽、4 个主动技能槽和通用闪避；
- 8～12 个被动升级；
- 4 种普通怪物；
- 1 种精英；
- 5 个承担不同机制检验的小 Boss；
- 1 个最终 Boss；
- 一局约 50 分钟；
- 仙坊由章节地图节点决定；
- 生命、法力、攻击力、护甲、移动速度、攻击速度、幸运、攻击距离、作用范围；
- 单人完整闭环；
- Listen Server + 1 个客户端的合作闭环。

本轮仍不需要：

- 武器进化；
- 跨局天赋树；
- 大量元素反应；
- 复杂地图程序生成；
- 排行榜；
- Dedicated Server。

## 24. 已冻结与仍待确认的玩法决策

已冻结：

1. 普通攻击由 `BasicAttackAbility` 决定，角色不硬编码攻击；
2. 每名玩家有四个主动技能逻辑槽 `Q / W / E / R`，所有角色共用同一技能池和效果；
3. 闪避是所有角色的独立基础能力；
4. 使用约 50 分钟的章节路线，五章各有一场小 Boss，之后是一场最终 Boss；
5. 仙坊由地图节点决定，不保证每战必进；
6. 单人死亡直接开始轮回；主动退出和异常中断可以从安全节点继续；
7. 成长同时包含数值提升与新战斗行为；
8. 局外只保留认知、关系、结局、图鉴和横向内容解锁，不保留永久战力；
9. 联机的共同路线、剧情和结局选择由房主决定，个人构筑仍由个人决定。

仍待确认：

1. 普通攻击最终采用方向键、鼠标还是自动索敌；
2. 当前 `F + Q/W/E/R + Space` 试玩布局的发布默认值、完整重绑定和手柄映射；
3. 合作救援是持续按键还是靠近自动救援；
4. 团队经验是否完全共享；
5. 生命球和法力球采用个人掉落还是全队共享；
6. 幸运最终影响升级、宝箱和掉落中的哪些项目；
7. 第一版期望同屏多少怪物；
8. 房主退出、断线重连和 50 分钟长局的恢复策略。

## 25. 机制验收标准

第一阶段机制达到以下条件才算成立：

- 玩家可以上下左右移动和攻击；
- 普通攻击行为来自 `BasicAttackAbility`，同一技能不因角色不同而改变规则效果；
- 所有角色都有独立于四个主动技能槽的基础闪避；
- 生命、法力、幸运、攻击距离和作用范围有独立可验证效果；
- 普通攻击不耗蓝，主动技能正确消耗和恢复法力；
- 攻击距离不会错误放大爆炸面积；
- 幸运不会直接提高暴击率，也不会影响必需通关掉落；
- 怪物、掉落、升级和结算由服务器权威决定；
- 相同 Seed 和决策可以复现升级和遭遇；
- 单人能够沿五章路线击败五个小 Boss，并完成最终 Boss 或死亡进入轮回；
- 两名玩家可以共享经验、独立构筑并完成救援；
- 全队倒地才失败；
- 所有关键属性在构筑页面可解释，不出现同名不同义的“范围”；
- W00/W01/W02 玩法和数据保持隔离。
