# 世界注册与解耦约定

## 目标

新增世界不得修改 W00 主世界的 C++、地图或资源，也不得向共享 GameMode 增加新的 `WorldId` 分支。世界通过一个 `WorldDefinition` 主资产自注册；主世界只消费注册结果。

## 新增世界

1. 在 `/Game/WorldWalker/Worlds/<WorldId>/` 下创建该世界自己的 `Maps`、`Data`、`Blueprints`、`Materials` 和 `ThirdParty` 等目录。
2. 创建一个 `WorldDefinition` Data Asset，至少填写唯一的 `WorldId`、玩家可见的 `DisplayName` 和本世界目录内的 `EntryMap`。
3. 非主世界保持 `bIsMainWorld=false`。需要出现在主世界时设置 `bExposeInMainWorld=true`；`PortalOrder` 控制稳定排序。
4. 若世界需要运行时组合或规则逻辑，在本世界目录中实现一个 Actor/Blueprint，并填入 `WorldRootActorClass`。共享 GameMode 会按定义生成它，不识别世界 ID，也不引用它的资源。
5. 地图、Root Actor 和世界资源一起提交即可。无需修改 `WorldTravelSubsystem`、`WorldHubLayout`、W00 地图、W00 资产或 cook 目录。

## 运行机制

- Asset Manager 把 `/Game/WorldWalker/Worlds` 下的 `WorldDefinition` 标记为主资产并纳入 cook；运行时使用同步 Asset Registry 查询，避免 GameInstance 初始化顺序造成漏注册。
- `WorldTravelSubsystem` 启动时自动发现全部定义，以 `WorldId` 建立注册表，并拒绝重复 ID。
- 注册时校验 `EntryMap` 与 Blueprint Root Actor 必须位于该定义所属的世界根目录；原生 Root Actor 可来自 `/Script`。跨世界入口引用会被拒绝。
- W00 根据 `bIsMainWorld` 识别自己，根据 `bExposeInMainWorld` 和 `PortalOrder` 枚举目的地。第一个目的地使用主题漩涡，其余目的地自动生成独立传送门。
- 旅行只读取目标定义的 `EntryMap`；返回主世界使用 `bIsMainWorld` 查询，不依赖 `W00_MainWorld` 常量。
- 打包配置覆盖整个 `/Game/WorldWalker/Worlds`，新世界不需要追加专用 `DirectoriesToAlwaysCook`。

## 边界

- 世界可以依赖明确的共享基础设施（角色基类、交互接口、通用 UI），但不能依赖 W00 或其他具体世界目录中的资源。
- 世界专属逻辑应放入自己的 Root Actor 或地图 GameMode；不要继续扩展 `AWorldWalkerGameModeBase::InitializeWorldContent` 的 ID 分支。
- W01 当前保留旧玩法分支以兼容已经完成的内容，后续可逐步迁移到自己的 `WorldRootActorClass`；这不影响新世界采用注册式入口。
